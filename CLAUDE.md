# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Imobia: an AI agent on WhatsApp that answers a solo real-estate broker's clients automatically, plus a kanban showing each client's stage in a property sale (any property type). The repo was restarted from scratch on 2026-10-26; only the app skeleton exists so far. The local folder is still named `loteAI`, but the old loteAI CRM is gone; don't reference or recreate it.

## Stack

- **TanStack Start** for the app, with **TanStack Query** for reads (route `loader` calls `queryClient.ensureQueryData`, components read with `useSuspenseQuery`), and **TanStack Form** for forms.
- Writes go through **server functions** (`createServerFn`) called from `useMutation`.
- **MUI 9** with a custom theme built from zero.
- **Bun** as runtime, package manager and toolchain.
- **Zod** for all validation (forms, server function inputs, env).
- **Postgres** (Docker locally and on the VPS), accessed through **Drizzle** with drizzle-kit migrations.
- **Better Auth** for login: email + password and Google. Multi-tenant SaaS: any broker signs up and sees only their own data, so domain tables are scoped to the owning user.

Still open, to be decided **after** the domain is modeled: WhatsApp provider. Deploy will target an existing OCI VPS later; there's no deploy workflow yet.

## Commands

```sh
bun install
docker compose up -d             # Postgres on :5432 (databases imobia and imobia_test)
bun run db:migrate               # apply drizzle/ migrations to DATABASE_URL
bun --bun run dev                # dev server on :3000
bun run build
bun run typecheck                # tsc --noEmit
bun fmt                          # format (config in bunfig.toml: no semicolons, single quotes)
bun fmt --check
bun lint                         # oxlint, config in .oxlintrc.json
bun run db:generate              # new migration from src/db/schema.ts
bun run auth:schema              # regenerate Better Auth tables in src/db/schema.ts
bun test                         # all tests (needs Postgres up)
bun test path/to/file.test.ts    # one file
bun test -t "test name"          # tests matching a name
```

## Layout

- `src/router.tsx` creates one `QueryClient` per router (that is, per SSR request) and passes it as router context; `setupRouterSsrQueryIntegration` handles dehydration/hydration. Routes reach it via `context.queryClient` in loaders.
- `src/routes/__root.tsx` is the HTML shell: Emotion `CacheProvider` → MUI `ThemeProvider` → `CssBaseline`, plus TanStack devtools.
- `src/theme/theme.ts` holds the MUI theme (`cssVariables: true`). It is intentionally near-empty; the theme is being designed from zero.
- `src/routeTree.gen.ts` is generated by the router plugin on dev/build (or `bunx tsr generate`); never edit it by hand.
- `src/auth/`: `server.ts` is the Better Auth instance (server-only), `client.ts` the browser client, `session.ts` the server functions routes call, `guard.ts` the redirect-to-`/login` logic. `/api/auth/*` is served by `src/routes/api/auth/$.ts`.
- Pages behind login live under `src/routes/_authed/`; its layout route puts `session` in the route context.
- Forms use `useAppForm` from `src/components/form.tsx` (TanStack Form + MUI fields) with Zod schemas as validators. Use `Link` from `src/components/Link.tsx` (MUI Link wired to the router).
- `src/env.ts` parses env vars with Zod at import time. Bun loads `.env` (dev) and `.env.test` (tests, committed, points at `imobia_test`).
- `bun test` preloads `test/setup.ts`: migrates the test database once and truncates the auth tables before each test. Tests hit real Postgres; no DB mocks.
- `vite.config.ts` sets `ssr.noExternal: ['@mui/*']` so MUI is bundled for SSR.

## Conventions

- `.env*` files are gitignored except `.env.example` and `.env.test` (test-only values).
- User-facing text (README, UI) is in Portuguese (pt-BR).
